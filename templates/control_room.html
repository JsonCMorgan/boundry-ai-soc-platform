🛡 MITRE ATT&CK Reference — Techniques Monitored by This System ▼
T1110 Brute Force
Credential Access
What you see in the feed
Many LOGIN_FAILED events from the same IP against the same username. Threshold: 5+ failures. May end with a LOGIN_SUCCESS (attack succeeded).
↔ vs T1110.003 Spray: brute force = one account, many passwords.
↔ vs T1110.004 Stuffing: brute force tries guesses, stuffing uses a known leaked list.

T1110.003 Password Spraying
Credential Access
What you see in the feed
LOGIN_FAILED events from one IP against many accounts, each with a low failure count (1–2 per account). Extra field contains sprayed_password=X.
↔ vs T1110 Brute Force: spray = many accounts, one password — designed to stay below lockout thresholds.
↔ vs T1110.004 Stuffing: spray uses a common password; stuffing uses unique credentials per account.
Full Playbook: Detection, Mitigation & IR →
T1110.004 Credential Stuffing
Credential Access
What you see in the feed
LOGIN_FAILED from same IP, 4+ different accounts — no sprayed_password marker. Suggests a leaked credential list. A subsequent LOGIN_SUCCESS from the same IP = CRITICAL.
↔ vs T1110.003 Spray: stuffing uses unique logins per account from a breach dump, not one shared password.
↔ vs T1110 Brute Force: stuffing hits many accounts once each; brute force hits one account many times.

T1190 Exploit Public-Facing Application
Initial Access
What you see in the feed
SEARCH events with SQL syntax in the query field: ' OR, --, UNION SELECT, DROP TABLE, 1=1. Attacker is injecting SQL into the search box.
↔ vs T1059.007 XSS: SQLi targets the database; XSS targets the browser of another user.
Key indicator: SQL keywords (SELECT, UNION) vs HTML/JS tags (<script>).
Full Playbook: Detection, Mitigation & IR →
T1059.007 JavaScript (XSS)
Execution
What you see in the feed
XSS_ATTEMPT events with HTML or JavaScript in the payload: <script>, onerror=, javascript:, <svg onload=. Goal: execute code in another user's browser.
↔ vs T1190 SQLi: XSS targets users' browsers to steal cookies or redirect; SQLi targets the database.
Key indicator: HTML/JS syntax vs SQL keywords.
Full Playbook: Detection, Mitigation & IR →
T1083 File & Directory Discovery
Discovery
What you see in the feed
DIRECTORY_TRAVERSAL events with ../ path sequences: ../../etc/passwd, %2e%2e%2f (URL-encoded). Attacker is trying to read files outside the web root.
↔ vs T1548 Priv Esc: traversal probes the filesystem via paths; priv esc probes restricted routes inside the application.
Both are discovery-type behaviours but at different layers.
Full Playbook: Detection, Mitigation & IR →
T1548 Abuse Elevation Control Mechanism
Privilege Escalation
What you see in the feed
PRIV_ESC_ATTEMPT events after a LOGIN_SUCCESS: authenticated user hitting /admin, /control-room, /.env, /api/admin. They're logged in but probing for higher access.
↔ vs T1083 Traversal: priv esc is about application routes (HTTP 403 doors); traversal is about filesystem paths.
Key pattern: always follows a successful login from the same IP.
Full Playbook: Detection, Mitigation & IR →
T1589.001 Gather Victim Identity Info
Reconnaissance
What you see in the feed
ACCOUNT_ENUM events: same IP probing 6+ different usernames rapidly. Attacker is mapping which accounts exist before launching a targeted attack.
↔ vs T1110 Brute Force: enumeration just checks existence (no password attempts); brute force comes after — it uses the confirmed usernames.
Think of this as the "shopping list" phase before the attack.
Full Playbook: Detection, Mitigation & IR →
T1078 Valid Accounts
Defense Evasion
What you see in the feed
LOGIN_SUCCESS with new_ip=true or unusual_hour=true in the extra field. Real credentials, no failure storm — but something about the context is off. Could be account takeover via phishing or credential theft.
↔ vs T1110 Brute Force: T1078 succeeds immediately with no prior failures — credentials were already stolen, not guessed.
Hardest to detect because it looks like a legitimate login.
